# Chart Marking Logic

This document details how trading signals generated by the strategy are visualized as markers on the dashboard chart.

## Mechanism

1.  **Signal Generation**: `gui/dashboard.py` calls `generate_signals` to compute entry/exit signals for the loaded dataframe.
2.  **Marker Construction**: `core/backtester.py` -> `run_backtest_with_markers(df, config)` iterates through the dataframe, simulating trade state to identify exact entry and exit points.
3.  **Rendering**: The list of markers is passed to the frontend via `chart.set_markers()`, which uses the **Lightweight Charts** API.

## Marker Types

Markers are distinguished by color, shape, and text.

### 1. Entries

| Signal | Color | Shape | Position | Text |
| :--- | :--- | :--- | :--- | :--- |
| **Long Open** | <span style="color:#21ba45">Green (#21ba45)</span> | `arrowUp` | `belowBar` | `LONG` |
| **Short Open** | <span style="color:#ef5350">Red (#ef5350)</span> | `arrowDown` | `aboveBar` | `SHORT` |

### 2. Exits

Exits are marked with a **Circle** shape. The color depends on the PnL and Exit Reason.

| Reason | Condition | Color | Text Example |
| :--- | :--- | :--- | :--- |
| **Win / TP** | PnL > 0 | <span style="color:#21ba45">Green (#21ba45)</span> | `TP (+1.50%)` |
| **Loss / SL** | PnL <= 0 | <span style="color:#c10015">Red (#c10015)</span> | `SL (-0.50%)` |
| **Trailing Stop** | `TrailingStop` log | <span style="color:#AB47BC">Purple (#AB47BC)</span> | `TS (+2.10%)` |
| **Trend Exit** | `RideEnd` log | <span style="color:#2962FF">Blue (#2962FF)</span> | `TrendEnd (+0.8%)` |
| **Breakeven** | `BreakevenFloor` log | <span style="color:#9E9E9E">Gray (#9E9E9E)</span> | `BE (0.00%)` |

### 3. Reversals

When a position flips directly from Long to Short (or vice versa), it is marked as a Reversal.

| Signal | Condition | Text |
| :--- | :--- | :--- |
| **Reverse to Long** | Short -> Long | `Rev LONG` |
| **Reverse to Short** | Long -> Short | `Rev SHORT` |

## Updates & Persistence

*   **Historial Data**: When the page loads, `run_backtest_simulation` calculates markers for the full loaded history (default 5000 candles).
*   **Live Updates**: `update_chart_loop` periodically re-calculates markers for the latest data chunk.
    *   **Smart Merge**: To avoid "Phantom Entries" (signals that appear temporarily and vanish), the dashboard replaces markers within the active time window while preserving historical markers.
